# مطبخ العائلة · Family Kitchen

نظام بسيط لإدارة طلبات مطبخ منزلي عائلي، بالعربية بالكامل، ويعمل على الجوال والكمبيوتر.

- **صفحة للزبائن** (`/`): يرى الزبون القائمة، ويختار الكميات، ثم يكتب اسمه وجواله ويختار الاستلام أو التوصيل والموعد، ويرسل الطلب بدون إنشاء حساب. بعد الإرسال تفتح له صفحة متابعة خاصة بطلبه تتحدث تلقائياً.
- **لوحة للعائلة** (`/admin`): يدخلها كل فرد من الأسرة بحسابه الخاص.
  - **الطلبات**: بطاقة لكل طلب، وزر واحد ينقله من جديد إلى مؤكَّد ثم قيد التحضير ثم جاهز ثم تم التسليم. فيه أيضاً زر واتساب برسالة جاهزة، وزر مدفوع/غير مدفوع، وتنبيه عند وصول طلب جديد من الموقع.
  - **طلب جديد (للمكالمات)**: اكتب رقم الجوال، فإن كان الزبون قديماً يظهر اسمه وعنوانه، ومعه زر «كرّر آخر طلب». فيه أيضاً أصناف خاصة غير موجودة في القائمة.
  - **التحضير**: كم تطبخون من كل صنف اليوم، وجدول الطلبات حسب الوقت.
  - **القائمة**: إضافة الأصناف وتعديلها، و«نفد»، وإخفاء الصنف من الموقع، وترتيب الأصناف.
  - **التقارير**: المبيعات، ومتوسط الطلب، والأصناف الأكثر مبيعاً، ومصادر الطلبات، والمبالغ غير المحصّلة.
  - **الإعدادات**: إيقاف استقبال الطلبات، ومواعيد الاستلام، ورسوم التوصيل، وحسابات العائلة.

## التقنيات

Python و Flask، مع SQL مكتوب مباشرة بدون ORM:

- **محلياً**: قاعدة SQLite في ملف واحد، بدون أي إعداد.
- **عند النشر**: PostgreSQL، ويكفي ضبط `DATABASE_URL`.

الجداول: `menu_items`، `customers`، `orders`، `order_items`، `users`، `settings`. تجدها في `app/db.py`.

## التشغيل على جهازك

```bash
git clone https://github.com/<your-username>/family-kitchen.git
cd family-kitchen
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # then edit SECRET_KEY
flask --app wsgi seed-menu      # optional: adds 6 sample dishes
flask --app wsgi run --debug
```

ثم افتح:

- صفحة الزبائن: http://127.0.0.1:5000
- لوحة العائلة: http://127.0.0.1:5000/admin. في أول زيارة تظهر صفحة لإنشاء الحساب الأول.

يمكنك أيضاً إنشاء حسابات من سطر الأوامر:

```bash
flask --app wsgi create-user umahmed --name "أم أحمد"
```

## النشر على الإنترنت (مجاناً للبداية)

الطريقة المقترحة: **Render** لتشغيل الموقع، و **Neon** لقاعدة PostgreSQL. الاثنان لهما خطة مجانية.

1. **قاعدة البيانات**: أنشئ حساباً في https://neon.tech ثم مشروعاً جديداً، وانسخ رابط الاتصال (يبدأ بـ `postgresql://`).
2. **الموقع**: في https://render.com اختر **New → Blueprint** واربطه بهذا المستودع، فيقرأ ملف `render.yaml` تلقائياً.
3. عندما يطلب `DATABASE_URL` الصق رابط Neon.
4. بعد انتهاء النشر افتح `https://<your-app>.onrender.com/admin` وأنشئ حسابك الأول **فوراً**، لأن صفحة الإعداد تبقى مفتوحة لأي شخص إلى أن يُنشأ أول حساب.
5. من **الإعدادات** اكتب رقم التواصل ومكان الاستلام ومواعيد العمل، ثم شارك رابط الصفحة الرئيسية مع زبائنك (في حالة واتساب، أو على إنستغرام، أو كرمز QR على العلب).

> ملاحظة: الخطة المجانية في Render تُنيم الموقع بعد فترة بلا زيارات، فيتأخر فتحه أول مرة نحو 30 ثانية. إن أزعجكم ذلك فالخطة المدفوعة الأرخص تحل المشكلة.

### متغيرات البيئة

| المتغير | الوصف |
|---|---|
| `SECRET_KEY` | سلسلة عشوائية طويلة. Render يولّدها تلقائياً |
| `DATABASE_URL` | رابط PostgreSQL. إن تُرك فارغاً تُستخدم SQLite محلياً |
| `KITCHEN_TZ` | المنطقة الزمنية، والافتراضي `America/Edmonton` (كالجاري) |
| `SESSION_COOKIE_SECURE` | اجعله `1` عند العمل على HTTPS |

## الأمان

- كلمات المرور مشفّرة (hash)، وكل النماذج محمية من CSRF.
- الأسعار تُحسب دائماً في الخادم، فلا يستطيع الزبون تغييرها.
- صفحة متابعة الطلب تعمل برابط عشوائي يصعب تخمينه، لا برقم الطلب.
- يوجد حقل مخفي يصدّ معظم الروبوتات التي ترسل طلبات وهمية.

## أفكار للمراحل القادمة

- رسائل SMS أو واتساب تلقائية عند تغيّر حالة الطلب (Twilio أو WhatsApp Business API).
- دفع إلكتروني (Stripe) أو تأكيد e-Transfer.
- حد أقصى للكمية من كل صنف في اليوم.
- نقل المخطط إلى Alembic عند الحاجة لتعديل الجداول.
- تحليلات وتوقّع الكميات حسب أيام الأسبوع.
